    # CLIMAGUARD AI — Codex Project Instructions

This repository contains CLIMAGUARD AI, a climate disaster intelligence and emergency-response application for Indradhanu Hackathon 2026.

## General Rules

1. Preserve existing working features.
2. Never rewrite unrelated modules unnecessarily.
3. Follow the existing architecture and styling conventions.
4. Prefer focused changes over large refactors.
5. Reuse components, services and types.
6. Never invent environmental observations, ML evaluation results, infrastructure locations or successful API responses.
7. Keep simulated information clearly labeled.
8. Use real API integrations wherever available.
9. Use Nugen-aligned model inference as the mandatory LLM integration.
10. Do not silently replace Nugen with another inference provider.
11. Keep API keys and privileged database credentials server-side.
12. Maintain a premium, clean, minimalistic and citizen-friendly UI.
13. Keep TypeScript and Python code modular and readable.
14. Run relevant checks after making changes.
15. Never claim tests have passed without executing them.
16. Document blockers and unavailable credentials honestly.
17. Avoid unnecessary dependencies, explanations and repeated code generation.
18. Maintain the existing project context in docs/PROJECT_STATUS.md after each major phase.

## Communication

- Implement directly instead of describing implementation plans.
- Ask questions only when essential credentials or decisions are genuinely required.
- Keep completion summaries brief.
- Report implemented features, tests and actual blockers.
- Do not start the next development phase automatically.
